# Strictly local tile codes — extraction from arXiv:2607.05897

Source: Bae, Park, "Strictly Local Tile-Code Architectures on Two-Dimensional Planar Lattices" (arXiv:2607.05897). These notes record the definitions used by `papers/planar_tile.py` (instances named `bp<family>_<n>_<k>_<d>`). Only this paper's TeX source, its figure files and its PDF were consulted.

The four code families come from Liang, Eberhardt and Chen, "Planar quantum low-density parity-check codes with open boundaries" (Ref. [17]; PRX Quantum 6(4), 2025, doi:10.1103/qv65-vmzr), which was not available here. The boundary conventions below were therefore reconstructed from this paper's Fig. 1, its n formulas and the tile-code construction of arXiv:2504.09171 (see `papers/new/2504.09171.md`).

## Definitions

Locators: Sec. II.A ("Bulk and boundary stabilizers", "Polynomial Representation", Eqs. (1)–(2), "Code Grafting"), Table I, Fig. 1.

- **Layers:** the lattice is `Lx x Ly` with open boundaries. L qubits sit on horizontal edges and R qubits on vertical edges. Each layer is restricted to `0 <= i < Lx`, `0 <= j < Ly`. The builder's positions are L(i,j) at `(i+0.5, j)` and R(i,j) at `(i, j+0.5)`, as drawn in Fig. 1.
- **Checks:** Eqs. (1)–(2) give `f = 1 + x + x^a y^b` for the L part and `g = 1 + y + x^c y^d` for the R part, over the Laurent ring. The X check is `(f, g)`. The Z check is the conjugate pair `(gbar, fbar)`, with `hbar(x,y) = x^-1 y^-1 h(x^-1, y^-1)`.
- **Normalization:** `f_norm = x^alpha y^beta f` and `g_norm = x^gamma y^delta g`, where `alpha = -min(0,a)` and so on. The two are normalized separately. A monomial `x^i y^j` of `f_norm` (or `g_norm`) is the L (or R) qubit at offset `(i,j)` from the check's anchor.
  - Worked example in the text: for the [[288,8,12]] family, `f_norm = x + x^2 + y^2` and `g_norm = 1 + x^2 y + x^2 y^2`.
  - Fig. 1 (Lx = Ly = 6) highlights one bulk weight-6 X check and one weight-4 boundary X check. Both are reproduced exactly by `bp288_72_8_4`.
- **Grafting:** "unnecessary" boundary qubits are removed. The text names R qubits on the bottom boundary and L qubits on the rightmost boundary, with the same number of boundary lines as Liang et al. The n values in Table I are after grafting.
- **Builder rule:** the construction of arXiv:2504.09171 with a rectangular box equal to the bounding box of `f_norm` and `g_norm`.
  - The Z tile is the (T2) image of the X tile. This equals `(gbar, fbar)` up to a common translation.
  - X boundary anchors: `By-1` rows below and above the bulk. Z boundary anchors: `Bx-1` columns left and right.
  - Grafting means deleting qubits that lie in no X check or in no Z check, then dropping empty checks.
  - Fig. 1 shows exactly this anchor set for Lx = Ly = 6: 4 columns x 8 rows of X checks, drawn at anchor + (1,1), and 8 columns x 4 rows of Z checks, drawn at face centres anchor + (1.5,1.5).

## Distances

- **Method:** none is stated. Table I lists [[n,k,d]] and attributes the families to Ref. [17]. No section describes a distance computation, and the two Sec. III.C instances come with only their parameters.
- **Exception, `bp288_288_8_12`:** it is the same code, up to qubit relabeling with X and Z exchanged, as `tile_288_8_12` of arXiv:2504.09171. Its d = 12 is stated there as exact by ILP. This is checked by `planar_tile.isomorphic()`, and recorded in `same_code_as` and `d_method`.
- **No guaranteed dx = dz:** no instance of this paper is X<->Z self-dual under the relabeling group tried (per-layer array symmetries, layer exchange). The open boundaries break the bulk X/Z symmetry, so dx and dz can differ.
- **Two decoding problems:** the paper itself argues, in Sec. III.B, that the X- and Z-error decoding problems differ only near the boundaries. Its supporting check is that the torus codes with the same f, g have isomorphic X and Z Tanner graphs.

## Circuit-level information

- **No routing (Sec. III.A):**
  - The paper uses the BB-code schedule of Bravyi et al., with L and R parts measured in parallel.
  - It is an "eight-round" cycle: initialization, six CNOT layers and measurement. Reduced-weight boundary checks use the same schedule.
  - In the standard noise model, the ancillas of truncated checks get idle noise during their unused CNOT ticks (Sec. II.B).
  - The d = 4 no-routing circuit has TICK depth 33 (Appendix B). That is consistent with 8 ticks per round over N = d = 4 rounds, plus a final readout.
  - Which polynomial term goes into which CNOT layer is not stated.
- **Routing (Sec. III.A, Table IV, Appendix C with Figs. 6–9):**
  - Every ancilla follows the same routing word over {L, R, U, D}, one SWAP per letter. X and Z ancillas start at separate offsets `delta_X` and `delta_Z`, given relative to the stabilizer tile. Each SWAP moves the swapped data qubits the opposite way.
  - CNOTs are packed into sub-ticks between the SWAP steps. Even rounds run the time reverse of the odd rounds, so data returns home every two rounds.
  - Valid words come from a three-phase exhaustive search. Phase 1 checks that each ancilla visits its whole support. Phase 2 orders the CNOTs subject to the CSS form of condition (b′) of Gehér et al.: for each overlapping X/Z pair, the number of shared qubits where the X CNOT acts first must be even. Phase 3 merges disjoint CNOTs into sub-ticks.
  - The authors state that every ancilla meets each support qubit exactly once per round and that the detector error model is deterministic.

- **Noise and decoding:**
  - Two noise models: Table II (standard: init and measurement flips with probability p, idle DEPOLARIZE1(p), two-qubit gates including SWAP DEPOLARIZE2(p)) and Table III (an SI1000 variant with native CNOT and SWAP at DEPOLARIZE2(1.5p)).
  - N = d rounds per experiment; the per-round rate is extracted as in Sec. II.C.
  - Only Z-check syndromes are decoded, i.e. X errors. The decoder is BP+OSD (OSD-CS order 7, min-sum scaling 0.5, at most 2000 iterations; Appendices A–B).
  - Thresholds are in Table V, and the qubit footprint against the rotated surface code is in Sec. III.C and Appendix E.
- **Not reported:** no circuit-level distance, for either circuit, and no repository, code or circuit files.
- **Can the routed circuits be rebuilt?** Not uniquely. Table IV and Figs. 6–9 fix the bulk schedule only up to conventions the paper leaves open:
  1. The physical qubit grid: where X and Z ancillas sit relative to the L/R data, and the units and reference point of `delta_X` and `delta_Z`. In the data-frame figures, the ancilla moves two sites per SWAP.
  2. Boundary handling. In Fig. 1, ancillas of boundary checks lie outside the data region (rows y = -1 and y = 6, columns x = -0.5 and 6.5). A uniform word would SWAP them with sites that hold no qubit. The paper does not say how truncated checks are routed.
  3. Initialization and measurement ticks relative to the 15/18 routing ticks, and the detector and observable definitions. The paper says only "deterministic"; decoding Z checks suggests a Z-basis memory.
  4. The CNOT slot of the sixth Z support qubit in Fig. 8.
  5. For the no-routing circuit, the assignment of the six terms to the BB schedule.

  A rebuilt Stim circuit would need explicit choices for each of these. With no circuit distances in the paper, there is nothing to validate a rebuild against except thresholds.

## Open questions and limitations the paper flags

- The routing schedules are optimal only within uniform, translation-invariant words. Non-uniform protocols or co-optimized placement might do better (Sec. IV).
- Thresholds depend on BP+OSD with fixed hyperparameters (Sec. IV).
- Only the X-error problem is simulated. Equality with the Z-error threshold is argued, not simulated (Sec. III.B).
- `nu` is a per-family fit parameter, since d does not grow linearly with the lattice size (Sec. III.B).

## Recorded ambiguities and assumptions

- **Anchors for families [[188,8,9]], [[131,7,7]] and [[88,6,6]]:** not given in the paper. The builder uses the Fig. 1 convention of family [[288,8,12]] (X boundary top and bottom, Z boundary left and right). The other choice, X boundary left and right, also reproduces every n and k, but it is the same code with X and Z exchanged. This holds at every size: the side-swapped code is the Hadamard image of the code built with X and Z tiles exchanged, and that code is a relabeling of the original (see the 2504.09171 notes). It was also checked numerically at one or two sizes per family. So d is unaffected by this choice, while dx and dz would trade places. Exchanging the roles of the L and R layers gives literally the same code.
- **Grafting wording versus the builder:** the text says R qubits on the bottom and L qubits on the right are removed. The builder's rule removes only R qubits: the bottom row and right column for [[188,8,9]], the bottom two rows and right column for [[131,7,7]], and the right column for [[88,6,6]]. Taken literally (R bottom plus L right, disjoint layers), the text cannot give the [[188,8,9]] and [[131,7,7]] counts. Those formulas need the removed lines to overlap at a corner, i.e. to lie in one layer. The builder's removal matches all Table I formulas exactly.
- **Sizes of [[338,8,13]] and [[392,8,15]]:** only the parameters are given, and n = 2LxLy for this family. For 338, 169 = 13² forces 13x13. For 392, 196 = 14² also factors as 7x28 or 4x49; the builder uses 14x14 because every Table I size of this family is square.
- **What could still differ from the authors' matrices:** the boundary check sets of Liang et al., if they are not the 2504.09171 anchor rows and columns. Any such set with the same n and k would have to differ by more than the side choice, which is ruled out above. n, k and Fig. 1 (for family [[288,8,12]]) are the only checks available.
- **Fig. 1 ancilla positions:** X ancillas are drawn at anchor + (1,1) and Z ancillas at face centres. This is circuit geometry and does not affect the check matrices.
