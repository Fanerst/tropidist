# Routing codes — extraction from arXiv:2606.25330v2

Source: [Routing Codes: High-Rate Quantum LDPC Codes with Short, Parallel Non-Local Connectivity](https://arxiv.org/html/2606.25330v2). This file records the definitions used by `papers/routing.py`, rather than author code or supplementary data. Only the named paper was consulted.

## Geometry and check matrices

Locators: Section II, Eqs. (1)–(5), Proposition 1; Appendix A, proofs of Propositions 1 and 2, Eq. (10).

The physical lattice is `Z_l × Z_m`; all dimensions below are even. Physical site `(x,y)` has module index `x*m+y`. Initial roles are:

- Data: `x+y` even, giving `n=l*m/2` data qubits.
- X syndrome: `x` odd and `y` even, giving `n/2` X checks.
- Z syndrome: `x` even and `y` odd, giving `n/2` Z checks.

Data columns and check rows are ordered by increasing initial physical-site index. A role is attached to its initial label and moves with each SWAP. At layer `t`, the current X syndrome position moves by `v_t`, the current Z syndrome position by `w_t`, and the data role at the destination moves back to the syndrome's former position. All coordinates are reduced modulo `(l,m)`.

For each initial syndrome label, its check support is the set of initial data labels encountered along this physical routing. Eq. (5) maps the support points to monomials. One representative X check starts at `(1,0)` and one representative Z check at `(0,1)`; all rows of each type are their even-even torus translates. Proposition 1 requires the even-even coefficients of `P(x,y) Q(x^-1,y^-1)` to vanish over GF(2), equivalently `H_X H_Z^T=0`.

Proposition 2's sufficient construction requires both `v=w` and an individually palindromic sequence. Table 3 instead allows `w=reverse(v)` without requiring `v=w`; for these instances the module derives both supports and checks commutation directly. Proposition 3 also requires identical, palindromic, nonnegative vectors and `sum(v)<(l,m)` componentwise. In particular, the weight-11 `(20,20)` instance has `sum(v)=(24,5)`, so Proposition 3 does not automatically establish its temporal condition.

## Circuit and fault support

Locators: Section III; Appendix B, Eq. (17); Appendix C.2; Appendix D.1, Eq. (26).

The default primitive is `CXSWAP=SWAP*CNOT`: the CNOT uses the X syndrome as control or the Z syndrome as target, then exchanges the physical locations of the two roles. At each syndrome cycle, initialize X syndromes in `|+>` and Z syndromes in `|0>`, execute the parallel routing layers, and read each syndrome in its own basis at its current physical position.

Section III's final paragraph specifies alternating forward and backward syndrome cycles. After the forward cycle with `(v,w)`, use `(-reverse(v),-reverse(w))` for the backward cycle. It returns every role label to its initial physical site and measures the same check again in reversed contact order. A round is one forward or backward cycle, so an odd total number of rounds ends with moved data and syndrome positions. The module tracks these positions for both syndrome records and final data readout.

Memory boundary convention: initialize all data in the chosen memory basis; first-round detectors include only checks of that basis. Later check detectors compare consecutive measurements of the same initial syndrome label. Final detectors compare the last corresponding syndrome record with the final data parity on its initial-label support. All `k` CSS logicals in the memory basis are included as observables. This realizes Appendix C.2's measured and final syndromes with temporal difference encoding. Detector coordinates use `(check_index,0,t,3)` for Z checks and `(check_index,0,t,0)` for X checks, retaining the matrix row order.

Fault support is the full 15 nonidentity two-qubit Paulis after each CXSWAP; preparation and measurement basis flips with probability `p`; and X/Y/Z on every idle qubit, each with probability `p/3`. Two-qubit depolarization assigns probability `p/15` to each supported Pauli. Noise on ordinary single-qubit Clifford gates is omitted. Appendix C.2 uses generic CNOT terminology for its 15-error locations; Section III identifies the actual routing gates, and D.1 explicitly identifies its omission of single-qubit gate noise with the CXSWAP compilation.

The iSWAP implementation requires the local Cliffords in Appendix B, Eq. (17): `CXSWAP=(H⊗I)(S†⊗S†) iSWAP (I⊗H)`. With those local gates noiseless, the ideal action is identical and the full depolarizing fault support is invariant under the local Clifford Pauli permutation. Thus the paper's bounds apply to this CXSWAP fault-support model. Using physical iSWAP gates would add those local Clifford wrappers and basis changes; directly replacing CXSWAP by bare iSWAP would not implement the same syndrome circuit. Including wrapper gate noise would introduce additional fault locations and would change the specified model.

## Recorded ambiguities and assumptions

- **Distance label at length 80:** Table 1 reports `[[80,8,7]]`, whereas Tables 2 and 3 report `[[80,8,8]]`. The module keeps the Table 1 tuple in `CODES[80][2]`, identifies the Table 3 construction with the output tag `80_8_8`, and does not alter its matrices to reconcile the labels. Exact iterative-deepening code-capacity searches in both bases found distance 8 and exhausted all smaller weights; independently checked witnesses and threshold records are in `results/papers3/routing/code_distances.json`. Thus the explicit definition has distance 8, agreeing with Tables 2/3.
- **Nonlocal vector at length 90:** Table 1 lists `(4,1)` but Table 3's explicit sequence uses `(2,1)` in both directions. The module uses Table 3, the stated source of complete generating parameters.
- **Current roles in Eq. (2):** Section II initially defines `X,Z,D` by initial sites, but its stated motion in Section III is relative to the current syndrome position. Read the role membership in Eq. (2) at each layer as current, moved role sets. Reading it as the fixed initial parity classes would contradict the stated forward routing and generally route syndrome roles into syndrome roles.
- **Composition order in Eq. (3):** With conventional right-to-left function composition, the first and middle expressions in Eq. (3) match chronological routing, but the printed definition `S_t=σ_1∘...∘σ_t` reverses the order needed by the final expression. Using `S_t=σ_t∘...∘σ_1` makes `S_(t-1)^-1 σ_t S_(t-1)` agree with the preceding palindrome and the position recurrence. The implementation follows the explicit recurrence and contact tracking, avoiding the inconsistent shorthand.
- **Preparation/readout idle timing:** D.1 specifies noise after idle operations but does not give their durations or a tick-level preparation/readout schedule. The module takes parallel preparation and parallel readout to consume one tick each, and applies one data idle depolarization during each. No qubit idles in any two-qubit layer, since every layer is a complete matching.
- **Why this idle convention does not add new distance mechanisms:** A data Pauli in the preparation interval can be propagated through its first CXSWAP into one of that gate's 15 supported output Paulis. A data Pauli in the readout interval commutes with all syndrome measurements and equals a supported data-only Pauli after its last CXSWAP. These idle faults therefore duplicate existing detector/observable support columns. Varying the number or duration of these idle intervals can change probabilities but cannot change the set of single-fault supports or the unit-fault circuit distance in this full two-qubit Pauli model. This argument assumes no extra operations or idles inserted between incomplete entangling sublayers.
- **Number of distance-test cycles:** Appendix C.2 does not state a cycle count for its reported circuit-distance sampling. Appendix D.2's `N=10` is explicitly for logical error-rate simulations. The pipeline round count is consequently a task-selected finite memory length, and equality with a tabulated upper bound should be interpreted with that boundary convention recorded.
- **Final syndrome boundary:** Appendix C.2 describes a final data-error syndrome but does not explicitly specify whether it is obtained through noisy destructive data readout or ideal analysis of residual data Paulis. The builder uses the requested memory experiment: final data measurement in the memory basis, with readout flips, detectors for the matching check type, and all memory-basis logical observables.
- **Sufficient conditions versus individual verification:** Several Table 3 sequences have `v!=w`, and the `(20,20)` weight-11 path exceeds Proposition 3's no-wrap bound. The paper states in Section IV that commutativity and circuit feasibility were checked separately outside the sufficient subclasses. The builder checks layer matching, CSS commutation and noiseless detector determinism directly rather than treating Proposition 3 as a proof for those instances.
