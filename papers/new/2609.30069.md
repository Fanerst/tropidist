## 1. Codes listed

### 1.1 Families and weights

**CPM-PP (CSS)**, parameters (J, L, P): n = L·P; H_X and H_Z are each J·P × L·P; every check has weight L; every column has weight J in H_X and J in H_Z (so each qubit is in 2J checks); design rate 1 − 2J/L; k = LP − rank H_X − rank H_Z (Sec. III.1, Eq. 5).

**Halved CPM-PP (non-CSS)**: n = L·P/2, k = k_parent/2, ⌈d_parent/2⌉ ≤ d ≤ d_parent (Eq. 20). Checks are the J·P folded parent X-checks; Sec. IV.1 says halving never increases the supplied check weights, so check weight ≤ L (a parent check hitting both members of a pair gives one Y). The abstract gives check weight 10 for the (4,10) instances [[90,21,11]], [[140,31,15]], [[200,43,20]]; Sec. VII.4 gives check weights at most eight for the two [[52,15,·]] codes. Qubit degree after folding is not stated for the PP family **[inference: ≤ 2J]**.

**Five-block balanced-product template (App. C)**: CSS parent with n = 5ℓ, k = ℓ, check weight 9, data-qubit degree 3 per basis on four block columns and 6 on the fifth; two halved non-CSS instances (Table 5).

### 1.2 How distances were determined (App. B, captions of Tables 7/8, Figs. 3/7/10)

- Lower bounds: a complete branch-and-bound search (irreducible-cluster principle of Dumer–Kovalev–Pryadko, grown through unsatisfied checks, with cyclic-symmetry root reduction for CPM lifts and admissible pruning bounds b1, b2, and b3 for the stabilizer case). For halved codes a certified parent-distance lower bound D is used as an extra pruning rule, Eq. (61): prune when w + y + 2(W − w) < D.
- Upper bounds: explicit logical operators, found with QDistRnd, sQetch and other existing distance finders (refs [49, 2, 67]).
- Exact when the two coincide. For CPM-PP CSS codes all kernel vectors have even weight, so exclusion through d0 − 2 proves d ≥ d0 (App. B.1); this shortcut does not carry over to Pauli weight (App. B.2).
- Table 7 caption: distances written "≤ d" are upper bounds from an explicit logical operator; unqualified distances are exact. Fig. 3 caption: filled markers = exact from completed exhaustion, open = upper bound from a witness.
- Table 8 caption does not itself say "exact"; Figs. 7 and 10 describe the CPM-PP frontiers as exact-distance. In 2607.14091 the three (5,10) rows carry a dagger meaning contributor-reported distance; in 2609.30069 Table 8 they carry no qualifier.
- Table 5 (five-block): parent and fold distances are upper bounds only.
- No distance in the paper is a proved theorem for a specific instance other than via these computer searches; App. A gives the family bound d ≤ (J+1)! (24 for J=3, 120 for J=4) under rank/size conditions.

## 2. Construction data

### 2.1 CPM-PP definition (Sec. III.1, Definition 1) — formulas exact

- For s ∈ Z_P, C(s) is the P×P circulant permutation matrix whose nonzero entry in row a lies in column a − s (indices mod P).
- Fix positive integers J, P and an even positive integer L. M = (M_ij), 0 ≤ i,j < J, is a J×J array; each M_ij is a partition of Z_L into L/2 disjoint unordered pairs.
- Exponent arrays E = (e_{iℓ}), D = (d_{jℓ}) ∈ Z_P^{J×L} must satisfy, for every 0 ≤ i,j < J and every {u,v} ∈ M_ij,

  `d_{j,u} − e_{i,u} ≡ d_{j,v} − e_{i,v} (mod P)`    (Eq. 2)

- Check matrices:

  `H_X = ( C(e_{iℓ}) )_{i,ℓ},   H_Z = ( C(d_{jℓ}) )_{j,ℓ}`    (Eq. 3)

- Orthogonality: the (i,j) block of H_X H_Z^T is `Σ_{ℓ=0}^{L−1} C(e_{iℓ}) C(d_{jℓ})^T = Σ_ℓ C(e_{iℓ} − d_{jℓ})` (Eq. 4), and paired terms cancel over F_2.
- `k = LP − rank H_X − rank H_Z` (Eq. 5).
- Optional search constraint (mixed distinctness), with m_ij(B) = d_{j,u} − e_{i,u} for B = {u,v}: `m_ij(B) ≠ m_ij(B′) for distinct B, B′ ∈ M_ij` (Eq. 6).
- Gauge freedom: `e′_{iℓ} = e_{iℓ} + τ_ℓ + α_i,  d′_{jℓ} = d_{jℓ} + τ_ℓ + β_j` (Eq. 9) preserves orthogonality, ranks, girth, distance. Partial gauge fixing used: `e_{0ℓ} = 0 (0 ≤ ℓ < L)` (Eq. 10).
- Search steps (Sec. III.2): pick J, L and a prime P; backtrack over perfect matchings to get M (no edge reuse in a row/column; no triangles if girth ≥ 8 wanted); solve `A_M x = 0`, `A_M ∈ Z_P^{(J²L/2)×2JL}` (Eq. 8); sample E, D; apply Eq. 6 and cycle tests; build matrices and verify; run the App. B logical-operator search. Note the tables contain composite P (18, 20, 22, 28, 30, 32, 40, 45, …) although the search description says prime P.

### 2.4 Symplectic halving (Sec. IV.1) — formulas exact

- Definition 3: if a CSS code on 2n qubits can be ordered so that `H_X = (A | B), H_Z = (B | A)` (Eq. 13), the halved code on n qubits has binary symplectic check matrix `H_halved = ( A | B )` with A the Pauli-X part and B the Pauli-Z part (Eq. 14).
- Folding map for a fixed-point-free involution π with π(S_X) = S_Z, choosing one endpoint q_i per pair: `F_π(a) = (x|z), x_i = a_{q_i}, z_i = a_{π(q_i)}` (Eq. 15). Commutation: `B_sp(F_π(a), F_π(b)) = a^T π(b)` (Eq. 16). `S_fold = F_π(S_X), N_fold = F_π(ker H_Z)` (Eq. 17). Weight: `wt_P(F_π(a)) = wt(a) − c_π(a)` (Eq. 19). Swapping the chosen endpoint of a pair is a local Hadamard (locally Clifford equivalent, same Pauli weight).
- Proposition 4 (CPM halving criterion): given a permutation ρ of block rows, a fixed-point-free involution σ of block columns, η ∈ Z_P with η² ≡ 1 (mod P), row offsets α_j, column offsets β_ℓ with β_{σ(ℓ)} = −η β_ℓ, if

  `D_{j,ℓ} = η E_{ρ(j),σ(ℓ)} + α_j + β_ℓ (mod P)`    (Eq. 21)

  then the parent halves under the qubit involution

  `π(ℓ, t) = ( σ(ℓ), η (t + β_ℓ) )`    (Eq. 22)

  and the halved code has blocklength LP/2. The Z-check (block row j, row coordinate a) maps to the X-check (block row ρ(j), row coordinate η(a − α_j)).
- η = +1: plain involution, π(ℓ,t) = (σ(ℓ), t + β_ℓ), β_{σ(ℓ)} = −β_ℓ. η = −1: reverse involution, π(ℓ,t) = (σ(ℓ), −t − β_ℓ), β_{σ(ℓ)} = β_ℓ. Modulo gauge: `D_{j,ℓ} = η E_{ρ(j),σ(ℓ)}` and `π(ℓ,t) = (σ(ℓ), η t)`. ρ can be taken as the identity. With the constraint built in, `T_{i,j}(ℓ) = E_{i,ℓ} − η E_{j,σ(ℓ)} − β_ℓ − α_j (mod P)` (Eq. 23) must take values in equal pairs across ℓ.
- For none of the halved instances does the paper print σ, ρ, η-specific offsets, E, or the folded check matrix. For [[92,25,8]] the parent E_X, E_Z are printed (2.3) but the involution π is described only by its properties (check-exchanging, π T = T^{-1} π, every T^t π fixed-point free) plus footnote 4; it would have to be solved for from Eq. 21 with η = −1 **[inference: a small search over σ, ρ, α, β; uniqueness not addressed by the paper]**.

## 3. Syndrome-extraction circuit

### 3.1 What the paper says

There is no circuit figure, no gate-order table, no schedule listing, no ancilla layout, and no statement of how mixed X/Y/Z checks of the non-CSS codes are measured (which two-qubit gates, which ancilla basis). Searching the full text: no occurrence of "hook", "effective distance", "Stim", "flag", "layer", "CZ"; "CNOT" appears only in a remark about transversal gates; "ancilla" only in "ancillary-gadget".

- **Non-CSS codes (Sec. IV.3).** Schedules were obtained by, in the paper's words, "searching for lowest-depth schedules that satisfy the commutation constraints" (Sec. IV.3). The resulting depth is not stated. Noise model: circuit-level depolarizing at p = 0.1%, with depolarizing noise on two-qubit gates, resets and measurements, no idling error, and noiseless state preparation and final measurement (justified by the absence of transversal initialisation/measurement for non-CSS codes). N_r = 20 syndrome-extraction rounds. Decoder: hierarchical — several tiers of BP and relay-BP, then integer-programming fallback. Comparator: d = 11 rotated surface code, same noise model and N_r, belief matching. No circuit-level distance is reported for any non-CSS code.
- **CSS codes (Sec. VI.2).** For [[530,216,12]] ((3,10), check weight 10) and [[518,228,16]] ((4,14), check weight 14): schedule depth equals the check weight, found by block-wise scheduling of the protograph and optimised for circuit-level distance and 4-cycle count. Reported circuit-level distance **upper bounds: 10 and 14**, i.e. two below the code distances. The tool used for these bounds is not named. 20 rounds at p = 0.1%, the idling-free circuit-level noise model of ref. [76] (arXiv:2604.16209); hierarchical decoder (fast BP, relay-BP, integer programming) on the single-basis detector error model.
- The proxy `p_L ∝ (p / p_th)^{d_circ/2}` (Eq. 24) is used with d_circ = 10 and 14.

## 6. Bottom line for circuit-distance testing

1. **Explicit circuit / schedule: none.** The paper gives two one-sentence descriptions of how schedules were found and no gate order, depth (for non-CSS), ancilla layout or measurement convention. Any circuit distance computed now would be for a schedule we design, not the authors'.
2. **Published circuit-level distance claims to compare against:** only the two CSS codes [[530,216,12]] (upper bound 10) and [[518,228,16]] (upper bound 14), depth-L schedule from block-wise protograph scheduling. Both have n > 400; both have exponent files on the Kasai page and in the kasaikenta GitHub repository (same parameters and P; identity with the simulated instance not stated).
3. **Headline non-CSS codes cannot be rebuilt** from public material: exponents, pairings and involutions are unpublished and ref. [59] is empty.
4. **What can be rebuilt now (n ≤ 400):** [[184,50,10]] CSS from the paper; several CSS CPM-PP codes from the Kasai page; the five-block [[320,64,≤12]] / [[160,32,≤11]] and [[275,55,≤14]] from Table 5 (representation conventions to be fixed by trial: check commutation, k, weights, zero fixed points, Y counts 0 of 1152 and 12 of 1968); [[92,25,8]] after solving Eq. 21 for the reversing involution and checking against footnote 4 and the weight-8 witness.
5. Open ambiguities: (J,L,P) of the simulated [[95,22,11]]; whether Table 8 distances for the (5,10) rows are independently certified; the [[876,298,22]] vs ≥ 20 discrepancy; index conventions for L[·]/R[·] in App. C; uniqueness of π for [[92,25,8]].
