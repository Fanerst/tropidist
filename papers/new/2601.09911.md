## Code definitions: cited-paper lattices chosen by the lead

Shift paper Table I, p.3; Eqs. (1)--(3), pp.3--4. Cell `(i,j)` represents
`x^i*y^j` and is indexed `i*m+j`. Data blocks are R followed by L; check rows
have the same cell order. The polynomial term order is the displayed order:
`A1=B1=1`, `A2=x`, `B2=y`.

| nominal key family | implemented ell,m,alpha | A | B | paper n,k,d | original literal ell,m,alpha | original literal n,k; ranks Hx,Hz |
|---|---|---|---|---|---|---|
| 72,72s,72d,72m | 6,6,0 | 1+x+x^-1*y^-3 | 1+y+x^3*y^-1 | 72,12,6 | 6,6,0 | 72,12; 30,30 |
| 120,120s,120d,120m | 6,10,4 | 1+x+x^-2*y | 1+y+x*y^2 | 120,8,12 | 10,6,4 | 120,0; 60,60 |
| 144,144s,144d,144m | 12,6,0 | 1+x+x^-1*y^-3 | 1+y+x^3*y^-1 | 144,12,12 | 12,6,0 | 144,12; 66,66 |
| 170,170s,170d,170m | 5,17,-7 | 1+x+y^-4 | 1+y+x^4 | 170,16,10 | 17,5,-7 | 170,0; 85,85 |

Eq. (1) specifies `y^m=1`, `x^ell*y^alpha=1`: lattice vectors
`(ell,alpha)` and `(0,m)`. Winding once in positive x subtracts alpha from y.
X check u acts on R at `A_i*u` and L at `B_i*u`; Z check u acts on R at
`bar(B_i)*u` and L at `bar(A_i)*u`. Thus Hx=[A|B], Hz=[B^T|A^T].
The historical audit found that all four original literal definitions satisfy
CSS commutation and have check weight six. Independent reconstruction using
`stabcode.Torus` and `shift_matrix` gave the same original ranks/dimensions,
so the discrepancy was not due to the cell reduction convention.

Cited Ref.[30], arXiv:2503.03827, Table 2, gives the same twisted polynomials but
different lattices: 120 has `(0,10),(6,4)` and 170 has `(0,17),(5,-7)`.
Those lattices give (120,8) and (170,16), as independently checked during the
historical audit. They differ from Table I plus Eq. (1) by the allocation of
ell and m to x and y. **Reading chosen by the lead:** use these cited-paper
lattices for nominal 120/170; retain literal shift-paper lattices as `120lit`
and `170lit`. Those audit-only keys have k=0, paper distance/claimed circuit
bound `None`, and `build` rejects circuit runs. The polynomials were retained.

Bare numeric command-line keys are coerced to int by run_parallel; CODES also

## Literal static schedule

Table II, p.3; §II.A, p.4. Notation `Z Ai` means
`L(bar(A_i)*u) -> Z(u)`; `Z Bi` means `R(bar(B_i)*u) -> Z(u)`;
`X Ai` means `X(u) -> R(A_i*u)`; `X Bi` means `X(u) -> L(B_i*u)`.

Seven CNOT layers, in chronological order:

1. Z B3
2. Z B2; X B1
3. Z A3; X A1
4. Z A1; X A3
5. Z A2; X A2
6. Z B1; X B3
7. X B2

Reset and measurement bracket the layers: nine paper timesteps. X ancillas
are prepared/measured in X and Z ancillas in Z, inferred from the usual CSS SEC.
The text calls this one example among many variants (936 for the gross code).
It does not expressly identify the example as the memory benchmark schedule.
**Reading chosen by the lead:** s and unsuffixed keys repeat exactly Table II
in every cycle. No IBM circuit or previous distance result was substituted.

## Literal dynamic schedule and inverse shift

Table III, p.5; Eq. (5), p.4; Fig.2, pp.4--5. Same notation; `rev` exchanges
control and target. Eight CNOT layers in the first cycle and seven in the second:

| layer | first cycle | second cycle |
|---|---|---|
| 1 | Z A2 | rev Z A2 |
| 2 | Z A3; X A1 | Z A3; rev X A1 |
| 3 | Z B3; X B3 | same |
| 4 | Z B1; X B2 | same |
| 5 | Z B2; X B1 | same |
| 6 | rev Z A1; X A3 | Z A1; X A3 |
| 7 | Z A1; rev X A2 | X A2 |
| 8 | X A2 | absent |

First cycle resets X/Z and measures R/L; second resets R/L and measures X/Z.
Bases are not printed. SWAP absorption implies X/R are prepared/measured in X,
and Z/L in Z. There are ten then nine paper timesteps. The manuscript does not
specify whether its benchmarks repeat this pair or insert a single pair among
ordinary memory cycles. **Reading chosen by the lead:** d repeats the exact
Table III pair, `[first,second] * (rounds/2)`. m begins with `rounds` static
cycles and replaces cycles `rounds/2-1` and `rounds/2` (zero-based) by one
`first,second` pair. Both d and m require positive even cycle counts. s accepts
any positive cycle count. One Table III pair implements one shift; hence d
performs `rounds/2` shifts, m performs exactly one, and s performs none.

Undoing the cancellations identifies the first absorbed SWAP pairings as
`X(u) <-> R(x*u)` and `Z(u) <-> L(u)`. The second absorbed pairings are
`X(u) <-> R(u)` and `Z(u) <-> L(x^-1*u)`. Therefore original data follow

* R(u) -> X(x^-1*u) -> R(x^-1*u)
* L(u) -> Z(u) -> L(x^-1*u).

The literal table implements **x^-1**, whereas its caption selects Ai=A2,
Aj=A1 and claims **x**. The historical exact GF(2) conjugation check modulo
code/prepared-ancilla stabilizers verified x^-1 on all 12 X and 12 Z generators
for both 72 and 144; x matched zero of those generators. This is stronger than
observing uniform all-zero/all-plus memory states, which cannot distinguish
the shifts. **Reading chosen by the lead:** retain every printed gate and
test/report the actual x^-1 automorphism; do not reverse gates to fit the
caption. A1 versus bar(A1) at first-cycle step3 is immaterial because A1=1.

## Derived detectors, data frame and experiment endpoints

The paper gives no explicit cross-cycle detector formulas. **Reading chosen
by the lead:** use the formulas derived from the retained gate schedules,
in fixed physical coordinates. Set `N=ell*m`, `n=2*N`, and let `m_t^C(u)` be
the cycle-t measurement of type C, with cycles numbered t=0,...,rounds-1.
Each cycle records N Z outcomes in check-row order, then N X outcomes.

* Static or second cycle: `m_t^Z(u)=M Z(u)`, `m_t^X(u)=MX X(u)`.
* First cycle: `m_t^Z(u)=M L(u)`, `m_t^X(u)=MX R(x*u)`. The X result retains
  check label u, even though the measured physical data position is x*u.
* Initial boundary: `D_0^C(u)=m_0^C(u)` only for C equal to the memory basis.
* Interior boundary t>0: `D_t^C(u)=m_t^C(u) XOR m_(t-1)^C(x*u)` when the
  current cycle is second; otherwise `D_t^C(u)=m_t^C(u) XOR m_(t-1)^C(u)`.
  Both check types are included at every interior boundary. This covers
  static-to-first, completed-pair-to-first, second-to-static and static-to-static.

Let q be the number of completed Table III pairs. At every supported final
boundary, the physical image of initial data is
`P(R,u)=(R,x^-q*u)` and `P(L,u)=(L,x^-q*u)`. Thus q=0 for s, rounds/2 for d,
and 1 for m. During a first cycle after q completed pairs, data instead occupy
`R(u)->X(x^-(q+1)*u)` and `L(u)->Z(x^-q*u)`; the second returns both blocks to
R/L with displacement x^-(q+1). The current builder requires even d/m cycle
counts, so it never terminates in the half-pair frame.

Initial data are prepared in the memory basis. Final data are measured in that
basis at positions P(j), but final records `f(j)` are ordered by the initial
data index j. If `H_C[u]` is a check row in `matrices`, the terminal detector is

`D_rounds^C(u) = XOR_{v in supp(H_C[u])} f(P^-1(v)) XOR m_(rounds-1)^C(u)`.

Only memory-basis checks appear at the terminal boundary. Each of the k
`stabcode.css_logicals` generators `L_i^C` has observable
`O_i = XOR_{j in supp(L_i^C)} f(j)`: the physical final support is P applied
to the initial logical support. This follows the actual automorphism, rather
than treating the output as static memory. Detector coordinates are exactly
`(u,0,t,3)` for Z and `(u,0,t,0)` for X, including terminal t=rounds.

The historical ideal audit checked these transition conventions on its
literal s/d instances. Current nominal/m/noisy verification belongs to the
current results, not the historical audit. The printed CNOT layers are
translation invariant and contain no repeated qubit within a layer; acceptance
checks measure that property directly.

## Fault support chosen by the lead and SI1000 qualification

§II.D, p.6, specifies ideal initial/final preparation/measurement and
d_circ noisy intermediate rounds; CZ is the native gate. Ref.[49],
arXiv:2108.10457 §2 Tables 1--2, specifies channels:

| operation | SI1000 channel |
|---|---|
| CZ | following two-qubit depolarization p |
| single-qubit Clifford | following depolarization p/10 |
| reset in Z | following X flip 2p |
| measurement in Z | preceding X flip 5p |
| unused qubit in a timestep | depolarization p/10 |
| qubit neither reset nor measured when others reset/measure | extra depolarization 2p |

Idle channels stack. Neither paper prescribes a general CNOT-to-CZ/H compiler,
Hadamard cancellation/fusion policy or placement into timesteps. These choices
determine probabilities, noise locations and DEM statistics. Ref.[40], Tour de
gross §2.6, uses a different uniform CX circuit noise model and cannot fill that
gap. Section II.D's q=p/30 failure-spectrum approximation does not specify the
exact channel implementation used for Table I's distance search.

**Reading chosen by the lead:** distance experiments use uniform full CNOT
location fault support, implemented with default p=0.001:

| location | implemented channel in full and noidle |
|---|---|
| after each printed CX | DEPOLARIZE2(p), all 15 nonidentity two-qubit Paulis |
| after Z reset / before Z measurement | X_ERROR(p) |
| after X reset / before X measurement | Z_ERROR(p) |
| data preparation and final data measurement | the same anticommuting basis flip p |

In full, every qubit not acted on in a reset, CNOT or measurement layer receives
DEPOLARIZE1(p), including the data preparation/final-measurement layers. noidle
drops all those idle channels and retains every printed CX and basis-flip
location. `build(..., noise="full")` is the default; `noise="noidle"` is the
comparison. The lead explicitly declared data endpoints noisy. This differs
from §II.D's ideal data endpoints and is recorded as an experiment choice.

The qualification concerns **single-fault DEM support**, not SI1000 rates or
the paper's exact noisy Stim file. For a layer/order-preserving compilation
`CX(control,target)=H(target) CZ(control,target) H(target)`, a single-qubit Pauli
fault adjacent to CX can be propagated to one of the 15 Paulis already allowed
after CX. A qubit unused throughout that layer has the same one-qubit support
as full's idle channel. SI1000 resonator-idle channels add probabilities to
support already present at those unused reset/measurement locations. Reset
and measurement basis faults reduce to the anticommuting flip; commuting
faults have no effect on the initialized state or recorded bit. Therefore
full represents SI1000's single-fault support for that order-preserving
compilation **with the same chosen endpoint convention**, up to probabilities
and duplicate support. The qualification does not allow entangling gates to
be reordered, certify other compiler policies, or claim agreement with
SI1000's original ideal endpoints. noidle is a deliberate reduced fault set,
not a claimed SI1000-equivalent model. Fault probabilities do not define the
project's unweighted distance, while removing locations can change distance.

The original source gaps remain historical evidence: twisted lattice
convention, shift direction, identification of the simulated variants, full
CZ/H timesteps, cycle sequence and detector declarations. They have been
resolved for this reconstruction by the lead's readings, rather than by newly
obtained author files. The authoritative source locations for those files are
Data Availability, p.10 (source on author request), and Appendix B, p.12
(author Stim files in a planned public GitHub repository; no URL given).
No author repository, dataset, source archive, or fetched code was executed.

## Monomial-numbering audit requested by the lead

The lead subsequently supplied exact server results with b=d in both bases
for every code: 72=(6,6), 120=(8,10), 144=(8,8), 170=(10,10). Those server
numbers are supplied evidence, not additional locally executed searches.
The next comparison varies the unprinted correspondence between table labels
and polynomial monomials, without choosing a new default.

`build(..., numbering=(pa,pb))` accepts two permutations of `(1,2,3)`.
`pa[i-1]` is the 1-based position in the printed A polynomial of the monomial
called Ai in Tables II and III; pb has the same meaning for B. The default is
`((1,2,3),(1,2,3))`. Check matrices and their row order remain unchanged,
because permuting a polynomial's terms does not change its sum. Schedules,
measurement positions, cross-cycle comparisons and final data frame use the
chosen table labels. Exact comparison with all 20 existing saved default
circuits passed; no existing circuit/result was replaced by a renumbered one.

**Literal entry retained:** Table III Round 1 Step 3 has X(u) -> R(barA1 u).
This previously coincided with ordinary XA1 because printed A1=1. Numbering
now honors that bar explicitly, including the literal b1 diagnostic. It is
not silently changed to A1 when a nonidentity monomial receives that label.
The other table entries retain their original directions and bars.

For labeled exponents a1 and a2, the intended completed-pair shift is
`g=A1/A2` (exponent difference a1-a2). The first cycle measures
`MX R(A2 u)` and `M L(barA1 u)` in the order of check u. A second-cycle
detector compares current u with the preceding result at `g^-1 u=A2/A1 u`.
After q completed pairs, final data positions are g^q times the initial
positions, on both R/L blocks. These formulas reduce exactly to the original
printed-numbering experiment. Invalid schedules are reported instead of
changing the code checks or detector requirements.

`papers/shift_numberings.py` enumerates all 36 assignments, using one fresh
worker process and unique module per assignment, OMP=1, full noise, six
cycles and kmax=12. It checks disjoint layers and deterministic experiments
in both bases, then independently conjugates every X/Z logical generator
modulo code/prepared-ancilla stabilizers and tests every lattice translation.
The inferred shift is therefore verified rather than assumed from the final
readout permutation. Per-numbering data contain
`(valid_s,d_s,valid_d,shift_d,d_d)`; each distance field has Z/X entries,
with separate certified bounds and errors if a search is unfinished.
Only equality of certified lower and replay-verified upper bounds is labeled
an exact distance. Individual pipeline outputs, circuits and logs are retained.

The local driver defaults to two concurrent workers, k_coll=2, 30 seconds
per threshold, a 570-second worker cap and 3500-second sweep cap. Server
commands can disable the local caps explicitly; no server job was submitted
in this task phase. Completed exact per-basis outputs can be resumed.
