marked with <=. No author repository or external dataset was accessed.

Use x=S_ell tensor I_m, y=I_ell tensor S_m, H_X=[A|B], H_Z=[B^T|A^T]
(IX.1/IX.2 and the Table 30 caption). The concrete indexing convention is:
check (i,j) has index i*m+j; L data have indices 0..ell*m-1, R data ell*m..n-1;
row (i,j) of x^a*y^b has its one in column ((i+a) mod ell,(j+b) mod m).
Transpose changes (a,b) to (-a,-b). Reversing the entire shift convention
is a global inversion of site labels and gives equivalent matrices/circuits.

## Actual syndrome circuit and Pauli faults

Algorithm 1 (PDF p. 28): prepare all n ancillas in |+>; software relabeling
establishes the first alignment; perform parallel CX (X ancilla controls
data) and CZ (Z ancilla and data); between later term pairs apply the shared
long-ring shift and separate medium/short-ring shifts; measure all ancillas
in X. It has n data+n bare ancillas and 8/7/8 entangling layers per cycle.
There are no cat ancillas or flags in this circuit. Cat factories in XI
and cat-based logical measurements in XIII concern other instructions.
Algorithm 2 adds beacons and loss/leakage handling and is not reconstructed.
Section X.5, Fig. 17 / Table 12 distinguishes the ordinary Stim reference
without loss/leakage gadgets. The device micro-architecture in XX.1 is not
the base Algorithm 1 circuit.

Sections III, IV.3, Tables 2-3 (PDF pp. 9-10) define these rates:

| Location | Pauli channel |
| --- | --- |
| two-qubit CX or CZ | DEPOLARIZE2(p) after gate |
| preparation / single-qubit operation | DEPOLARIZE1(p/10) after operation |
| measurement | outcome flip p/10 |
| idle computational POC | DEPOLARIZE1(p/100) |
| transport step, moving and idle qubits | DEPOLARIZE1(p/2000) |

The builder applies these channels to Algorithm 1 and to memory initialization
and destructive readout, with zero loss and leakage. Every entangling layer
touches every data and ancilla qubit, so it has no idles. Data idle during
ancilla preparation and measurement. Transport is an ion permutation tracked
by the encounter list, not a noisy computational SWAP. Qubit IDs follow ions;
ancilla indices keep the check labels across cycles.

The abstract composite transport instruction is modeled as one transport
noise step per transition, w_check-1 per cycle. Algorithm 1 does not specify
the elementary route decomposition. Table 11 gives aggregate transport
times, not the full sequence of elementary noisy locations. Thus the emitted
probabilities are an explicit abstraction, not a reconstruction of every
device transport step. The *fault support and distance* are independent of
how many such single-qubit noise steps are inserted: between gates they
duplicate outcomes already available in adjacent DEPOLARIZE2 locations.
Preparation, readout, and idle faults likewise have equivalent outcomes in
the first/last adjacent entangling layer. The tests compare full and gate-only
undecomposed DEM column sets to check this equivalence for the built circuits.

Table 10 does not document its distance algorithm, number of SECs, memory
basis/boundary experiment, or a separate list of included Pauli locations.
The six-round memory boundary convention is the project-requested one.
The stated default ionic/moving Pauli model is used, rather than asserting
that the paper explicitly documents its distance-search implementation.

## Memory boundaries and symmetries

Data are reset/read out in the requested Z or X basis. Initial detectors
use checks of that basis; intermediate detectors difference consecutive
measurements of both check types; final detectors compare the final data
parities to the last same-basis check measurements. Detector coordinates
are (check,0,t,3) for Z and (check,0,t,0) for X, t=0..rounds. All k logical
operators from stabcode.css_logicals are observables of the final readout.
All nonidentity Z_ell x Z_m translations are candidate circuit symmetries:
50, 34, and 26 for Q102, Q70, Q54 respectively.

Exact checks and bounded local circuit searches are recorded under
results/papers3/walkingcat/; their stdout is under logs/papers3/walkingcat/.
Pipeline JSON uses the shared runner's legacy field
paper_circuit_distance_upper_bound; for this paper the stored value 9 is a
stated exact value, as the module notes and Tables 9-10 explain.

## Local outcomes

Both code distances were certified exactly with css_distance_problem and
cdist.search.distance(k_table=3, cover=True), exhaustive lighter thresholds,
translation symmetries, and independently checked syndrome/logical witnesses:
Q102 9/9, Q70 9/9, Q54 10/10 (Z/X memory bases). Reproduce with
`OMP_NUM_THREADS=2 .venv/bin/python papers/walkingcat_run.py --code-only`.

All six six-round circuit searches finished: exact circuit distance 8 in
both bases for every code, versus the stated 9 in Table 10. Each result has
certified lower bound 8 and a DEM-checked, physically replayed upper-bound
witness of weight 8. Sector reduction is exact; all 50/34/26 supplied
translations survive direct checks in run_parallel. The test script checks
translation generators and their explicit full group closure.

An independent Q54 Z audit moved an eight-fault witness entirely into bulk
round index 2, using only DEPOLARIZE2 outcomes at eight distinct gate
locations. Both DEM parity and physical replay produce no detectors and L0.
Thus adding/removing preparation, readout, idle, or transport noise, or
using longer boundary padding, cannot account for this weight-8 upper bound.
The detailed fault set is in results/papers3/walkingcat/audit_54_Z.json.

These are conditional results for the explicit printed-order numbering.
Since the paper never explicitly associates each indexed monomial with a
term, they do not establish a definitive contradiction of an otherwise
unpublished numbering. Resolving that issue requires the authors' numbered
generator/schedule inputs or a clarification of A_i and B_i; it cannot be
resolved from the extracted tables alone. No alternate ordering was tried
to make the distance agree with 9.
