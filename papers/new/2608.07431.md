### 2.6 How d was determined (main text "Code results" and §S6.1)

- **Certification stage (exact):** every reported instance is certified by exhaustive enumeration, done separately for X and Z. - Nothing is proved analytically about d of individual instances; the propositions give only upper bounds (Eqs. S46–S52).

### 4.2 Layout and round structure (paraphrase; formulas verbatim)

- Data atoms sit on a `kp×Lq` grid and check atoms on a `kp×Jq` grid, writing `C_{m}=C_{p}\times C_{q}`; rows carry the `H_k` index and the `C_p` component, columns carry the block index and the `C_q` component (Fig. 3 caption).
- Syndrome extraction runs in L rounds; round i applies a permutation element of the lift to the **check** atoms. For a direct-product code it factors into a rigid row move and a rigid column move, Eq. (4):

```text
	$$\sigma_{r,i}=h_{i}h_{i-1}^{T}\otimes c_{i}c_{i-1}^{T},\quad\sigma_{c,i}=c^{\prime}_{i}{c_{i-1}^{\prime}}^{T}.$$		
```

- Between consecutive rounds the rearrangement is the transition element `F_{i}F_{i-1}^{T}` (Fig. 3 caption). Cyclic permutations between the ancilla and the L data blocks happen in parallel with these moves (main text).
- §S5.1: there are L blocks of data qubits, J blocks of X ancilla and J blocks of Z ancilla (the sentence prints the condition on J as `J\geq L/2`, evidently a typo for ≤). The 2D arrangement of sites is said to be identical to Ref. [23], with `L+J` pairs of blocks placed vertically, but with some moves done more optimally. The qubit order of the check matrices maps directly to atom positions.
- Prop. 24 (restricted SPG, `C_{p}\times C_{q}=C_{m}`), moves for `i ∈ R` and for `i ∉ R` respectively, verbatim:

```text
	$\displaystyle\sigma_{r,i}$	$\displaystyle=h_{i}h_{i-1}^{T}\otimes c_{i}c_{i-1}^{T},$	
	$\displaystyle\sigma_{c,i}$	$\displaystyle=I_{J}\otimes c^{\prime}_{i}{c_{i-1}^{\prime}}^{T}.$	
	$\displaystyle\sigma_{r,i}$	$\displaystyle=h_{i}h_{i-1}^{T}\otimes I_{p}\cdot c_{i0}c_{i-1,0}^{T}\oplus...\oplus c_{ik}c_{i-1,k}^{T},$	
	$\displaystyle\sigma_{c,i}$	$\displaystyle=c^{\prime}_{i0}{c^{\prime}_{i-1,0}}^{T}\oplus...\oplus c^{\prime}_{ik}{c^{\prime}_{i-1,k}}^{T}.$	
```

- Entangling gate: each rearrangement is followed by one layer of parallel **CZ** gates between all paired atoms. `F_i` and `G_i` specify how the ancilla are arranged relative to the data; `F_{j}F^{-1}_{i}`, `G_{j}F^{-1}_{i}`, `G_{j}G^{-1}_{i}`, `F_{j}G^{-1}_{i}` are the changes from one CZ layer's permutation to the next (§S5.1).
- X and Z in the same cycle, in parallel (§S5.1, paraphrase): because the Z check matrix contains the inverse block permutations of the X check matrix, the permutation for the next X check and the next Z check are done together — the ancilla are permuted for the non-inverse (X) permutation, and half of the data is permuted by the same amount; permuting data instead of ancilla gives the inverse relative permutation between the Z ancilla and the data.

- Codes simulated: `[[132,30,12]]` and `[[672,336,12]]`, against the gross code BB `[[144,12,12]]`, pair-partition PP `[[232,62,12]]`, and the surface code at d = 11 and 13.
- Circuit: sampling with Stim [9] and decoding with a two-stage Relay-BP cascade [23] "on a greedy coloration syndrome extraction circuit" (§S6.2). So the simulated circuit is a greedy edge-colouring schedule, **not** stated to be the AOD move order of §4.3. Its gate order, depth and X/Z arrangement are not given.
- Noise: a standard error model in which measurement, readout and all gate errors are parametrised by a single physical error p. Idle errors are not included (as in [23]; justified by coherence times of tens of seconds). No further detail: the Pauli channel for one- and two-qubit gates, reset errors, the number of rounds `N_c`, and the memory basis are not stated.
- Reported quantity: probability that any logical qubit fails per cycle, `p_{L}=1-(1-p_{fail})^{1/kN_{c}}`. Surface code decoded with minimum-weight matching. Totals: `2.9\times 10^{9}` shots and `1.0\times 10^{4}` logical failures across the two GALA codes and four baselines.
- Fits: `C(p/p_{th})^{d_{eff}}` [8] and `p^{d/2}\exp(c_{0}+c_{1}p+c_{2}p^{2})` [3]. Pseudo-thresholds of the GALA codes about 0.38–0.41%.
- `d_eff` (fit exponent, not a distance): estimated 9.5 for `[[132,30,12]]` and 13.5 for `[[672,336,12]]` over the simulated range of p; the authors read this as near-threshold waterfall behaviour and call the extrapolation a rough estimate.
- Data points: both GALA codes reach `p_L ~ 5×10^{-8}` at `p = 1.5×10^{-3}` and `2×10^{-3}` (Fig. S3 caption; it misprints the second code as `[[676, 336,12]]`). Extrapolated to `p = 10^{-3}`: `[[672,336,12]]` about `5×10^{-11}` per logical qubit per cycle at overhead 3.0; gross about `2×10^{-12}` at overhead 24; pair-partition about `4×10^{-12}` at overhead 5.6. `[[132,30,12]]` at `p = 10^{-3}` with the full cascade including MILP [23] timed out at `5×10^{6}` shots with zero failures, giving an estimated ceiling of `10^{-8}`.
- **Circuit-level distance / effective distance / hook errors: no statement anywhere.** The word "hook" does not occur. The only fault-distance remarks concern logical gadgets: the homomorphic-measurement gadget has fault distance `d_{\mathcal{Q_{N}}}` (Prop. 23), and for a generic ZX-dual code `S_τ` carries a CZ across every τ-pair, which may reduce fault distance (§S7.3). The outlook says fault tolerance of the logical gates is left for future work.

## 8. Ambiguities, typos, and blockers

1. **J missing from Tables S3 and S4.** **[inference]** J = L/4 (2 for L = 8, 3 for L = 12). Support: the text ties rate ≥ 1/2 to J = L/4; Table S5 is the J > L/4 table. **[reader's check]** every L = 12 row of Tables S3/S4 has k ≥ n/2 + 4, which is the monomial bound (S45) `k/n ≥ 1 − 2J/L + 2(J−1)/n` at J = 3 (equality in all but `[[576,294,8]]` and `[[1008,510,10]]`), and every L = 8 row has k = n/2. Rebuilding and checking k will confirm.
2. **`[[720,360,12]]` cannot be rebuilt**: named twice, never tabulated. Likewise the n = 2160 instance.
3. **Exponent notation is defined only loosely.** The caption says tuple elements correspond to the factors of `C_m` and that semidirect lifts may need several tuples. **[inference]** round brackets `x^{(a,b,c)}` are components in the listed cyclic factors, in the order the group is printed; square brackets `x^{[s_0,…,s_{k−1}]}` are the per-block bottoms `\mathbf{c}=(c_1,…,c_k)` of (S34); a bare `x^{s}` inside a semidirect code is the uniform bottom `\textbf{1}\otimes x^{s}`. The bracket distinction is not spelled out.
4. **The action of the generator x is not written explicitly** (whether `x: j ↦ j+1` or `j−1`); only Definition 12's `[P_{g}]_{i,j}=\delta_{j=g(i)}` and the glossary entry defining `Z_n` as the cyclic group acting on `[n]`. **[inference]** for a cyclic factor the two choices differ by the group automorphism `x ↦ x^{-1}` applied everywhere, which should give a permutation-equivalent code; the non-abelian tops are pinned down by the printed multiplication table.
5. **`τ` for `S_2`** is not defined in the captions (necessarily the transposition). `S_2` tops are abelian although Definitions 15–16 call `H_k` non-abelian.
6. **Restriction set R** of `⋉_R` codes is not listed (implicit in the entries).
7. **Simulated circuit ≠ documented schedule**: the LER results use an unspecified greedy-colouring circuit, so they cannot be reproduced exactly, and the §4.3 move order is given without any accompanying simulation claim.
8. **Schedule under-specified** (see §4.4): Z-check pairing per layer, gate basis, a/b labels, measurement/reset steps.
9. **Typos seen** (transcribed as printed): `J\geq L/2` in §S5.1; `[[676, 336,12]]` in the Fig. S3 caption; `[672,336,12]]` with a missing bracket twice in §S6.2; example group written `S2\times S3\times S14` with `P=2*3*14=84` in §S5.1 (presumably `C_2×C_3×C_14`); `p=1.5^{1}0^{3}` and `p=2\times 10^{3}` for the data points; `2\times 10^{-}12`; Table 1 prints the baseline as `[[1152,580, 12]]` without the ≤ sign; the Fig. 3 image title is misspelt. Main text and supplement disagree slightly on search size (`10^5` codes, n ≤ 2500 versus `2×10^5` codes, n ≤ 3000) and on the second QDistRnd tier (`10^3` versus 1024).
10. **Figures not seen** (Fig. 1, 4, S1–S4, S6) — plots only as far as the captions indicate; unlikely to hold construction data, but unverified.

## 9. Bottom line for circuit-distance testing

- Code definition: available and complete enough to rebuild all 24 codes with n ≤ 700, subject to confirming J for Tables S3/S4 and the exponent conventions by reproducing the stated k (and, for `[[132,30,12]]`, `H_X = H_Z`, rank 51, `t_4` = 660).
- Circuit: only `[[132,30,12]]` and `[[672,336,12]]` have a published layer order, and turning it into a gate-level circuit needs the reconstruction in §4.4. For every other code a schedule would have to be invented (e.g. an edge-colouring circuit, which is what the authors simulated).
- The paper makes no circuit-distance claim to compare against; the only related numbers are the fit exponents `d_eff` ≈ 9.5 (`[[132,30,12]]`) and 13.5 (`[[672,336,12]]`).
