## Construction data

Definition II.1: for left cosets `x_i H`, `L(g)[i,j]=1` when
`g x_j H=x_i H`, and `R(g)[i,j]=1` when `x_j g H=x_i H`.
Construction 1: over GF(2), `Hx=[sum L(a_j) | sum R(b_j)]`,
`Hz=[(sum R(b_j))^T | (sum L(a_j))^T]`.

Table 2 caption fixes GAP **4.14.0** and these one-based enumerations:

```
G = SmallGroup(order, index)
H = Filtered(AllSubgroups(G), h -> not IsNormal(G,h))[s]
a indices: LeftCosets(G, Core(G,H))
b indices: LeftCosets(Normalizer(G,H), H)
```

`papers/coset.py` uses `Representative` for each indexed coset, retaining the
listed order of the a and b terms. The a action is invariant under the choice
of representative modulo the core, and the b action under the choice modulo H.
For the qubit/check order it uses `LeftCosets(G,H)` in GAP's returned order.
This final ordering is a simultaneous relabeling, so it does not change distance.
Equality of left cosets is tested by `y^-1*x in H`.
Matrix entries are accumulated with XOR, so coincident term edges cancel as
Construction 1 requires. Proposition III.1 gives an upper bound on check
weight; the tests check the reported maximum and the parity/degree bounds,
and print the observed weight set rather than assume every row has that maximum.

## Schedule

Section V defines the **row-to-column** convention `A_j(i)` for `L(a_j)` and
`B_j(i)` for `R(b_j)`. Thus the extracted arrays are inverse-action maps:
`A_j(i)=index(a_j^-1*x_i H)` and `B_j(i)=index(x_i*b_j^-1 H)`.
X gates are `X[i] -> D_block[P(i)]`; Z gates are
`D_block[i] -> Z[P(i)]`, giving the transposed supports in Hz.

Section VI specifies primary block a for both weights. Let X-A denote X gates
on D_L with an A term, Z-A denote Z gates from D_R with that term, and X-B/Z-B
denote the corresponding gates on D_R/D_L.

Weight 6, Section VI and Algorithm V odd branch (`S=Z`, `U=X`):
startup `R_Z`, then the eight simultaneous-operation layers per cycle:

| layer | X operation | Z operation |
|---|---|---|
| 0 | RX | Z-A1 |
| 1 | X-A2 | Z-A3 |
| 2 | X-B2 | Z-B1 |
| 3 | X-B1 | Z-B2 |
| 4 | X-B3 | Z-B3 |
| 5 | X-A3 | Z-A2 |
| 6 | X-A1 | MZ |
| 7 | MX | RZ |

The isolated terms removed from `g_Z=(a1,a3)` and `h_X=(a1,a3)` are both a1.
Algorithm V lines 17 and 22 require startup RZ and a reset at the end of every
cycle, including the final cycle. This is not a schedule with simultaneous
resets followed by six paired CNOT layers and simultaneous measurements.

Weight 8, Section VI: reset both check types, then X/Z term pairs
`(A2,A1), (A3,A4), (B1,B2), (B2,B1), (B3,B4), (B4,B3),
(A1,A2), (A4,A3)`, then measure both check types: ten layers per cycle.

The module computes simultaneous permutations commuting with each individual
A and B term. Such permutations applied to both check types and both data
blocks preserve every gate, preparation, measurement, and idle-noise layer.
For disconnected actions it returns internal automorphisms and equivalent
component swaps; these generate the centralizer without enumerating all products.

## Noise and memory-boundary assumptions

Section VI specifies anticommuting preparation flips, uniform nonidentity
two-qubit Pauli noise after CNOTs, uniform single-qubit Pauli idle noise, and
anticommuting measurement flips on ancillas, all with total probability p.
The implementation uses X_ERROR/Z_ERROR, DEPOLARIZE2 and DEPOLARIZE1.

- Idle noise is included in **every** layer, including preparation/measurement
  layers and the unused data block in the odd schedule's first/last CNOT steps.
  This follows the Section VI rule for every idle time step.
- Section V describes syndrome extraction on an existing data state. The memory
  wrapper prepares every data qubit in the memory basis, with a preparation flip.
  In weight 6 this preparation shares the required startup RZ layer; in weight 8
  it occupies a separate boundary layer. This endpoint choice is not specified
  by the paper. Both choices give `rounds*(w+2)+2` total TICKs including readout.
- The final data measurement gets a flip following the task's broader
  preparation-and-measurement fault-model instruction. Section VI explicitly
  mentions **ancilla** measurement noise; noisy data readout is a documented
  memory-wrapper extension. Data are idle during the last syndrome-measurement
  step and receive idle noise there.
- Dead/unprepared ancillas also receive idle noise in boundary layers. Such
  noise is erased by the next reset or cannot reach any later recorded output.

Detectors compare consecutive same-type measurements. At t=0 only checks in
the memory basis have a detector; at t=rounds, final data parity is compared
with the last same-type syndrome. Coordinates are `(i,0,t,3)` for Z checks and
`(i,0,t,0)` for X checks. All logical observables from `css_logicals` are included.
